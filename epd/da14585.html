快捷操作

对时、刷新状态、页面切换都走 Console 服务，不占用高速数据通道。

0 号设备信息页可看固件版本、面板尺寸、LP 时钟源与对时状态，右侧是微信赞赏码；5 号挪车页的号码在「挪车号码」页修改。OTA 或图片传输进行中时，设备会拒绝切页并回一条 WARN 日志。
默认关闭：写入时间会触发一次约 2 s 的整屏刷新，和下面的自动补写号码叠在一起，屏幕连闪两下很像「设备重启了」。需要时手动勾选，或点「对时」按钮单次执行。

显示选项

选项位会写进设备并掉电保存，改完立即触发一次重绘。

12 小时制：时钟页大数字显示「2:26 PM」，倒计时页顶行显示「26/11/22 日 2:26PM」；不勾 = 24 小时制（默认）。只改时间写法，不改日期。 七段数码管：不勾 = Inter Bold 现代数字（默认）；勾上 = LCD 电子表那种七段数码管。只作用于横屏时钟页的大 HH:MM 和倒计时页的超大天数，切换后立即重绘，断电重启仍然保持。
2020 年这类延期年份可运行时改到 7 月，无需重新编译固件。
生日 / 纪念日等每年重复的日子，时钟页底行右侧显示倒计时。

对时/切页会触发约 6.5 s 双遍整刷，期间 unix 不推进，紧接测量会得到假值； 自动观测先静置 30 s 再建基准。ppm 是「每秒攒分数、满 1e6 µs 才补 1 秒」的离散补偿， 范围 ±500，只能吸收逐板微调。大比例误差由网页直接改写 tick 折算系数（0.001 ms 精度， 写进 RTC1 掉电保留），再重新对时建基准继续闭环；超出 50..200 ms/tick 的荒谬结果只告警不写。
连接态与断开态是两个不同的系数：连着的时候协议栈把 100 ms 定时器按 30.8 kHz 折算成约 94 ms，断开之后按真实 32.768 kHz 走约 100 ms，比值 1.064，一个系数不可能两态同时准。 本页自动校正只标连接态（它必须在连着的状态下测）；台钟日常待机是断开态， 那个系数要用命令行 python tools/ble_client.py calidle --minutes 20 --apply 断开静置标定。

手动对时

留空则使用本机当前时间。时区范围 −12 .. +14，设备默认 UTC+8。

断电后软件 RTC 会丢失，重新连接时控制台可自动对时。若要把校准值持久化到 flash， 在固件里实现 esl_rtc_io_t.save_cal/load_cal 并调用 esl_app_rtc_setup()。

传输参数

逐包 ATT 写请求：每包等设备应答才发下一包，不会丢包

数据段用 带响应的写（Write Request），由 ATT 层节流；无响应写会被 Windows 蓝牙栈静默丢包，主机进度条到 100% 而设备只收到几 KB。传完会用 QUERY 核对设备实际落盘字节数再 COMMIT。

等待升级—
只写非运行 bank。 COMMIT 前目标 bank 的头恒为擦除态， 中途断电会继续启动旧固件；只有回读 CRC32 通过后才写 image header。 脚本绝不碰 0x00000 bootloader、0x38000 product header 和 0x39000 / 0x3a000 板级记录。
